# ระบบประเมินความพึงพอใจฐานกิจกรรม (Real-time)

ระบบโหวตความพึงพอใจฐานกิจกรรมอบรม 6 ฐาน (A-F) พร้อม:

1. ✅ **โหวตแบบเรียลไทม์** — ทุกเครื่อง/ทุกจอที่เปิดหน้านี้เห็นคะแนนอัปเดตพร้อมกันทันที (ใช้ Firebase Realtime Database)
2. ✅ **นำเข้าไฟล์ Excel/CSV ผลโหวตเดิม** ผ่านปุ่ม "นำเข้าข้อมูล" ในหน้า Admin — คะแนนที่นำเข้าจะถูก **บวกเพิ่ม** เข้าไปในฐานข้อมูล ไม่ทับของเดิม จากนั้นสามารถกดโหวตออนไลน์เพิ่มต่อได้ทันที
3. ✅ **หน้า Leaderboard** (`leaderboard.html`) แยกต่างหาก สำหรับฉายจอประกาศผลอันดับ 1-3 (โพเดียม) และ 4-6 (รายชื่อ) แบบเรียลไทม์

## ขั้นตอนที่ 1: ตั้งค่า Firebase (จำเป็น ต้องทำก่อนใช้งานจริง)

ระบบนี้ใช้ **Firebase Realtime Database** (ฟรี) เพื่อให้คะแนนโหวตซิงค์กันแบบเรียลไทม์ระหว่างหลายเครื่อง/หลายจอ โดยไม่ต้องมีเซิร์ฟเวอร์ของตัวเอง — เหมาะสำหรับโฮสต์บน GitHub Pages ซึ่งเป็นเว็บแบบ static

1. ไปที่ [Firebase Console](https://console.firebase.google.com/) แล้วกด **Add project** สร้างโปรเจกต์ใหม่ (ตั้งชื่อ เช่น `nsl-activity-voting`)
2. ในเมนูซ้าย ไปที่ **Build > Realtime Database** แล้วกด **Create Database**
   - เลือก location ที่ใกล้ที่สุด (เช่น `asia-southeast1`)
   - เลือกเริ่มต้นในโหมด **Test mode** ก่อน (จะแก้ Security Rules ในขั้นตอนถัดไป)
3. ไปที่ ⚙️ **Project settings > General** เลื่อนลงมาที่ **Your apps** กด ไอคอนเว็บ `</>` เพื่อสร้าง Web App (ตั้งชื่ออะไรก็ได้ ไม่ต้องติ๊ก Firebase Hosting)
4. Firebase จะแสดงโค้ด config ให้คัดลอกค่าเหล่านี้:
   ```js
   const firebaseConfig = {
     apiKey: "...",
     authDomain: "...",
     databaseURL: "...",
     projectId: "...",
     storageBucket: "...",
     messagingSenderId: "...",
     appId: "..."
   };
   ```
5. เปิดไฟล์ `js/firebase-config.js` ในโปรเจกต์นี้ แล้ว **แทนที่ค่า placeholder ด้วยค่าจริงที่คัดลอกมา** (แก้ทั้ง 6-7 บรรทัด)

### ตั้งค่า Security Rules (แนะนำ)

ในหน้า Realtime Database ของ Firebase Console ไปที่แท็บ **Rules** แล้วตั้งค่าดังนี้ เพื่อให้ทุกคนอ่าน/เขียนคะแนนได้ (เหมาะกับงานอีเวนต์ภายในองค์กรที่ไม่ต้องล็อกอิน) แต่ป้องกันไม่ให้แก้โครงสร้างข้อมูลมั่ว:

```json
{
  "rules": {
    "votes": {
      ".read": true,
      ".write": true,
      "$station": {
        ".validate": "newData.isNumber() && newData.val() >= 0"
      }
    },
    "history": {
      ".read": true,
      ".write": true
    }
  }
}
```

> หากต้องการความปลอดภัยสูงขึ้น (เช่น จำกัดให้โหวตได้เฉพาะช่วงเวลาอีเวนต์) สามารถปรับ Rules เพิ่มเติมได้ภายหลัง เอกสารเพิ่มเติม: https://firebase.google.com/docs/database/security

## ขั้นตอนที่ 2: ทดสอบก่อนอัปโหลด (ทางเลือก)

เปิดไฟล์ `index.html` ในเบราว์เซอร์โดยตรง (หรือใช้ extension เช่น "Live Server" ใน VS Code) เพื่อทดสอบว่าเชื่อมต่อ Firebase ได้ถูกต้อง — สังเกตป้าย "เชื่อมต่อเรียลไทม์แล้ว" มุมขวาบนของหน้าเว็บ

---

## ขั้นตอนที่ 3: อัปโหลดขึ้น GitHub และเปิดใช้งานผ่าน GitHub Pages

1. สร้าง repository ใหม่บน GitHub (public หรือ private ก็ได้ — ถ้า private ต้องมี GitHub Pro/Team เพื่อเปิด Pages)
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้น repository เช่น:
   ```bash
   cd nsl-activity-voting
   git init
   git add .
   git commit -m "Initial commit: NSL activity voting system"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<your-repo>.git
   git push -u origin main
   ```
3. ไปที่ repository บน GitHub > **Settings > Pages**
4. ในหัวข้อ **Build and deployment > Source** เลือก **Deploy from a branch**
5. เลือก branch `main` และโฟลเดอร์ `/ (root)` แล้วกด **Save**
6. รอสักครู่ GitHub จะแสดงลิงก์เว็บไซต์ เช่น `https://<your-username>.github.io/<your-repo>/`
7. เปิดลิงก์นั้น — จะเป็นหน้าโหวต (`index.html`) โดยอัตโนมัติ
8. หน้า Leaderboard สำหรับฉายจอ อยู่ที่ `https://<your-username>.github.io/<your-repo>/leaderboard.html`

## วิธีใช้งานแต่ละฟีเจอร์

### หน้าโหวต (Kiosk)
เปิดค้างไว้บนแท็บเล็ต/คอมพิวเตอร์ที่จุดโหวต ผู้เข้าร่วมแตะปุ่ม 👍 ที่ฐานที่ประทับใจ ระบบจะบันทึกและซิงค์คะแนนไปยังทุกเครื่องที่เปิดหน้านี้อยู่ทันที

### หน้า Admin
กดปุ่ม "หน้าสรุปผล (Admin)" มุมขวาบน แล้วใส่รหัสผ่าน (ค่าเริ่มต้นตั้งไว้ในไฟล์ `js/firebase-config.js` ตัวแปร `ADMIN_PIN`) จะเห็น:
- กราฟและตารางอันดับแบบเรียลไทม์
- ประวัติการโหวตล่าสุด
- ปุ่ม **นำเข้าข้อมูล (Import Excel/CSV)**
- ปุ่ม **ส่งออก Excel (.csv)**
- ปุ่ม **ล้างคะแนน**
- ลิงก์เปิดหน้า Leaderboard

### นำเข้าไฟล์ Excel/CSV ผลโหวตเดิม
รองรับไฟล์ที่ระบบนี้ส่งออกเอง (ทั้งไฟล์ .csv จากปุ่ม Export และไฟล์ Excel ที่แปลงมาจากไฟล์นั้น) โดยจะอ่านได้ 2 รูปแบบ:
- **ตาราง Audit Log** (แนะนำ — แม่นยำที่สุด เพราะเก็บเวลาการโหวตแต่ละครั้งไว้)
- **ตารางสรุปอันดับ** (คอลัมน์ อันดับ, รหัสฐาน, ชื่อฐานกิจกรรม, ชื่อแผนก, จำนวนคะแนนที่ได้, ร้อยละ)

คะแนนที่นำเข้าจะถูก **บวกเพิ่ม** จากยอดปัจจุบันในฐานข้อมูลเสมอ (ไม่ทับข้อมูลเดิม) หลังนำเข้าเสร็จ ผู้เข้าร่วมสามารถกดโหวตออนไลน์ต่อได้ทันทีโดยยอดจะนับต่อจากที่นำเข้าไป

### หน้า Leaderboard
เปิดแยกในแท็บ/จอโปรเจกเตอร์ต่างหาก แสดงอันดับ 1-3 แบบโพเดียม (🥇🥈🥉) และอันดับ 4-6 แบบรายการ อัปเดตค่าทุกครั้งที่มีคนโหวตหรือมีการนำเข้าข้อมูลใหม่ โดยไม่ต้องรีเฟรชหน้าเอง

## หมายเหตุด้านความปลอดภัย

- รหัสผ่าน Admin (`ADMIN_PIN` ในไฟล์ `js/firebase-config.js`) เป็นการป้องกันเบื้องต้นสำหรับกันคนเข้าใช้งานผิดพลาดในงานอีเวนต์เท่านั้น ไม่ใช่ระบบยืนยันตัวตนที่ปลอดภัยระดับสูง เพราะไฟล์ทั้งหมดเป็น static และมองเห็นซอร์สโค้ดได้จากเบราว์เซอร์
- ค่า Firebase config (`apiKey` เป็นต้น) เป็นค่าที่ตั้งใจให้เปิดเผยได้จากฝั่ง client (ไม่ใช่ secret) แต่ควรตั้ง **Security Rules** ตามคำแนะนำด้านบนเพื่อจำกัดรูปแบบข้อมูลที่เขียนได้
- หากต้องการใช้งานในหลายอีเวนต์ แนะนำสร้าง Firebase project แยกต่างหาก หรือเปลี่ยน path ของข้อมูล (`votes`, `history`) ตามรอบงาน
